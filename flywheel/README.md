# Flywheel Why

Trigger: user sends a screenshot of the DCA splitter Flywheel row and says **"flywheel why"**.

## Steps
1. Read the tickers from the screenshot.
2. Research each one live (WebSearch): price, recent news, earnings date,
   analyst moves, sector/macro backdrop.
3. Write `weeks/YYYY-MM-DD.md` using the previous week's file as the template:
   macro backdrop, same-bet warning, then per ticker: What / Why up / Why not /
   Main reason to grade. List sources at the bottom.
4. Add one row per pick to `scorecard.md` (grade date = pick date + 4 weeks).
5. Grade any scorecard rows whose grade date has passed: look up the price,
   decide whether the main reason actually happened, fill in Result, update the tally.
6. Reply in chat SHORT but EXPLAIN THE MECHANISM: for each pick, a short paragraph on
   WHY it might go up — the cause-and-effect reasoning (e.g. "utilities trade like bonds,
   the hike pushed money into bonds, the selloff was about rates not the business, so
   if rate fear fades money flows back"). Not just a list of facts/news. Add the main
   risk in a few words, the same-bet warning if any, a one-line "common thread" across
   the picks, and how old picks graded. Also save this reasoning into the weekly file
   under "Why it might go up (the reasoning)". See weeks/2026-09-24.md as the model.

Keep the "Why not" honest — the point is learning whether catalysts predict anything,
not cheerleading the technicals.
